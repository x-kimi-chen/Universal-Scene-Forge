5发现的缺陷与修复

D-1 · 依赖体检 open3d 误报（已修复）
现象：体检对 open3d 恒报「未安装」，即使本机已正确安装。
根因：deps.py 的 REQUIRED_PY 以模块别名 "o3d" 作为 find_spec() 的探测键，而 open3d 的真实导入名是 open3d—— find_spec("o3d") 永远失败。该缺陷在体积优化改造（引入 open3d 体检项）时引入， 属新代码笔误而非历史遗留。
修复：REQUIRED_PY 探测键改为 "open3d": "open3d"。
复测：T3a 六项全部 ok=True（见第 4 章），误报消除。
字段内容
严重级别中（不阻断主流程，但使按需安装引导失效）
引入版本v0.9.0 体积优化改造
影响范围「依赖体检」对话框 open3d 项显示；不影响其他五项与安装功能
修复文件app/utils/deps.py（1 行）
验证状态已修复 · 复测通过（修复随最新构建进入安装包）

6安装后用户路径：open3d 按需安装

体积优化的核心设计是「包体最小化 + 高级功能按需补装」。用户安装 75.5 MB 安装包后， 在需要网格重建（OBJ/FBX/GLB/BLEND 导出）时的完整路径如下：

  1. 开箱即用功能视频抽帧、COLMAP 对齐、3DGS 训练（子进程隔离环境）、 Blender/Max/Maya/Houdini/C4D 桥接、FBX 五级降级链、UE5 推流——全部随包提供。
  2. 触发高级功能勾选 OBJ 网格导出并启动流水线；若 open3d 缺失， 该阶段明确报错并提示进入「依赖体检」。
  3. 一键补装「依赖体检」中 open3d 项显示红色缺失， 点击「一键安装」经镜像源 pip 补装（约 145 MB，装到用户 Python 环境，不污染安装目录）。
  4. 复检通过体检转绿后重新运行流水线，网格重建（泊松 + LOD + 顶点色回传）正常。
设计权衡说明
若将 open3d 随包分发，安装包将回到 ~190 MB+，违背 <100 MB 目标； 按需安装让「不需要网格重建」的用户（仅做 3DGS 训练与 FBX 导出）零负担， 需要的用户多一次点击。对无外网环境，可在「依赖体检」中改用内网镜像源， 或手动 pip install open3d 后重新体检。
