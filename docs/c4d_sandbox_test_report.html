环境级阻断（沙箱）
结论
Cinema 4D 桥接（OBJ → FBX）无法在 TRAE 代理沙箱内完成端到端验证，根因是沙箱的文件系统白名单 拦截了 C4D 启动时对其配置目录 %APPDATA%\Roaming\Maxon\... 的写入，导致 Commandline.exe 无限挂起、c4dpy.exe 崩溃。桥接代码本身无缺陷：超时看门狗、进程树终止、[USF] 协议解析、 异常上抛与降级链切换均在本次测试中按设计运行。建议按第 5 章指南在正常桌面环境完成最终验收。

T4 · c4dpy.exe 替代入口诊断（决定性证据）

项内容
操作直接运行 c4dpy.exe hello2.py（脚本 import c4d 并打印版本）
结果BLOCKED-ENV 进程崩溃，退出码 3221225477（0xC0000005 访问冲突）
关键证据沙箱在进程终止时输出了明确的拦截日志（见下方），点名被拦截路径为 Maxon 配置目录 ✅
TRAE Sandbox Error: process crashed; pid=40368, code=3221225477
TRAE Sandbox Error: hit restricted
  Not allow operate files: <用户本地路径>/AppData\Roaming\Maxon\Maxon Cinema 4D 2025_789E552B_p
  Hint: If the tool supports running outside the sandbox, you should try requesting
  to run this command outside the sandbox.
根因判定
C4D 家族进程（Commandline.exe / c4dpy.exe）启动时必须读写 %APPDATA%\Roaming\Maxon\Maxon Cinema 4D 2025_<hash> 配置目录（首启创建、 授权状态、用户偏好、着色器缓存）。TRAE 代理沙箱的文件白名单不包含该目录： Commandline.exe 的写入被静默阻塞 → 初始化死等（T1/T2/T3 挂起）； c4dpy.exe 则直接访问冲突崩溃（T4，并留下明确拦截日志）。这与前一会话 「沙箱阻止 C4D 访问 NVIDIA/Intel 缓存路径」的结论相互印证，属环境限制而非产品缺陷。

5正常桌面环境验证指南

以下三种方式任选其一即可完成验收。方式 A 最接近真实用户路径，推荐优先执行。

预检清单（所有方式通用）

  1. Cinema 4D 2024+ 已安装且完成授权（交互式主程序能正常打开、无授权弹窗）；
  2. 任务管理器中无残留的 Cinema 4D.exe / Commandline.exe / c4dpy.exe 进程；
  3. 至少手动启动过一次 Cinema 4D（确保 %APPDATA%\Maxon 配置目录已生成）。

方式 A · 全流程 GUI 验证（推荐）

  1. 启动软件
    双击 UniversalSceneForge.exe（或安装版快捷方式）。确认右侧 DCC 状态矩阵中 Cinema 4D 指示灯为绿色。
  2. 构造降级场景
    点击 调用路径设置，将 Blender 一栏手动指定为一个不存在的路径（如 C:\not_exist\blender.exe），保存——这将强制 FBX 走降级链直达 C4D。验证完成后记得清除恢复自动。
  3. 运行重建
    输入一段 10–20 秒的环绕视频，勾选 fbx 导出格式，点击 ▶ 开始重建。
  4. 观察判据
    日志控制台依次出现：
[INFO] Blender 导出失败, 降级: ...
[INFO] Cinema 4D 无头启动: usf_xxxxx.py
[INFO] Cinema 4D 完成, 产物 1 个: usf_scene.fbx      ← 验收通过标志
[INFO] FBX 由 Cinema 4D 降级导出
  • 产物检查：usf_work\output\usf_scene.fbx 存在且 > 1 KB，可用 3D 查看器打开即为完整验收。

    • 方式 B · 单桥脚本验证

    项目仓库已内置自动化脚本 tests\e2e_c4d_bridge.py，在普通命令行窗口（非代理沙箱）中执行：

    cd /d <项目仓库本地路径>
.venv\Scripts\python.exe tests\e2e_c4d_bridge.py

[E2E] 成功: C:\...\usf_scene.fbx  大小=xxxxxB  耗时=xx.xs
[E2E] PASS

    脚本会自动构造立方体 OBJ → 调用桥接 → 校验 FBX 产物 → 清理临时目录。看到 PASS 即验收通过。 预期耗时 20–90 秒（取决于 C4D 启动速度）。

    方式 C · 最小诊断（30 秒快速判定环境是否健康）

    将下面两行保存为 hello.py，双击或用命令行运行 "C:\Program Files\Maxon Cinema 4D 2025\Commandline.exe" -script=hello.py：

    print('[USF] PROGRESS 50 c4d python alive')
print('[USF] DONE')

    判定：10–60 秒内进程退出（退出码 0）且输出两行协议文本 = 环境健康、桥接可用； 超过 2 分钟无输出 = C4D 初始化被阻断（此时按第 6 章排查表处理）。

    验收判据汇总

    判据通过标准
    Commandline.exe 响应方式 C 在 60 s 内输出 [USF] DONE
    OBJ → FBX 转换方式 B 输出 [E2E] PASS，FBX > 1 KB
    GUI 降级链方式 A 日志出现「FBX 由 Cinema 4D 降级导出」且绿灯
    超时保护人为把 c4d_timeout_s 改为 10（settings.json）复跑方式 B，应 10 s 报超时而非永久挂起

    6桌面环境仍失败时的排查表

    现象可能原因处置
    Commandline.exe 挂起（方式 C 超时）授权未激活 / 许可服务不可达先打开交互式 Cinema 4D 完成一次授权激活，再重试
    日志出现 no FBX export 类错误FBX 导出插件未随安装启用C4D 内菜单 Extensions → 插件管理器 确认 FBX/导入导出组件已启用
    导入 OBJ 失败（no objects）OBJ 文件含非 ASCII 路径且编码异常把工作目录迁移到纯英文路径后重试
    导出 FBX 为 0 KB场景为空（OBJ 解析成空文档）用记事本检查 OBJ 头部合法性；用其他查看器验证 OBJ 本身
    多版本 C4D 共存走了错误版本三级探测命中了非预期安装调用路径设置 手动指定目标版本的 Cinema 4D.exe
    备注
    Houdini 桥（hython.exe）未受本次沙箱问题影响路径——其配置写入量远小于 C4D； 但若桌面环境验证 Houdini，同样可用 tests\ 下的对应脚本思路构造最小 OBJ 用例。
