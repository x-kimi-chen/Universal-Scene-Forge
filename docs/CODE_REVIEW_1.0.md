# 1.0 代码质量整改记录

本文件记录 1.0 版本定稿前的一轮代码整改，用于软件著作权登记材料中的"技术特点与改进"说明。每条包含改动内容、原因、影响与验证方式。

## 一、重构：统一子进程终止逻辑

**改动内容**：新增 `app/utils/proc.py`，提供唯一的 `kill_tree(proc)`；`c4d_bridge`、`houdini_bridge`、`max_bridge`、`metashape_bridge`、`ue5_bridge` 五个桥接中各自的 `_kill_tree` 改为调用该函数，删除重复实现。

**原因**：同一段"超时/取消时终止进程树"的代码在 8 个桥接中重复，且实现不一致——有的用 `system_tool("taskkill.exe")` 取 System32 绝对路径，有的直接写裸命令 `taskkill`，依赖 PATH 解析。Windows 下当前目录优先于 PATH，裸命令存在被同名程序劫持的风险，也与项目自身的安全约定（外部程序只走绝对路径）相矛盾。

**影响**：终止行为统一为绝对路径调用，异常一律回退 `proc.kill()` 且不向上抛出，避免掩盖原始失败原因；后续新增宿主只需调用一个函数。

**验证**：全仓 `grep '"taskkill"'` 归零；`py_compile` 通过；走查调用点覆盖超时、用户取消两条路径。

## 二、缺陷修复：打包版命令行静默退出

**改动内容**：新增 `app/utils/console.py`（`ensure_console()`、`notify_output_saved()`），`main.py` 在进入 `--check-deps` / `--cli` 前先接回标准流。

**原因**：PyInstaller 以 `console=False` 打包后进程没有控制台，`sys.stdout` 为 `None`。命令被正常接收、报告却无处可写，用户看到的是"执行了但没有任何输出"——实测 `UniversalSceneForge.exe --check-deps` 即为此现象，而源码方式 `python main.py --check-deps` 正常。

**影响**：从 cmd/PowerShell 启动时附加到父控制台；双击启动时新建控制台窗口；两者都不可用时把报告写入 `~/.universal_scene_forge/logs/cli_*.txt` 并以消息框提示路径。命令行退出码语义不变。

**验证**：源码方式回归无变化；打包版在无控制台场景下输出落盘并提示。

## 三、缺陷修复：命令行中断退出码

**改动内容**：`main.py` 入口捕获 `KeyboardInterrupt`，打印"已中断"后以 130 退出。

**原因**：Ctrl+C 与"阶段失败"原先都表现为非零退出码，脚本无法区分是用户主动中止还是流水线出错。

**影响**：退出码约定变为 0 全部成功 / 1 阶段失败 / 2 参数错误 / 3 输入或环境阻断 / 130 用户中断。

**验证**：CLI 运行中按 Ctrl+C，退出码为 130。

## 四、性能优化：模糊帧评分并行化

**改动内容**：`Ingester.filter_blurry()` 的逐帧清晰度评分从串行列表推导改为 8 线程 `ThreadPoolExecutor.map`。

**原因**：清晰度评分是"解码 + Laplacian"的 CPU/IO 混合负载，OpenCV 解码期间释放 GIL，串行执行时 300 帧要数秒，且发生在流水线最前端，直接影响用户感知的启动等待。

**影响**：中位数与阈值算法不变，筛选结果完全一致；60 张 1280×720 图像的实测耗时由 0.513 s 降至 0.044 s（约 11.7 倍），300 帧规模由约 2.5 s 降至 0.2 s 量级。

**验证**：`tests/manual_bench_blur.py` 对比串行与并行结果，逐帧分数完全一致、保留帧数一致（40/60）。

## 五、异常补强：无控制台与无输入的可预期失败

**改动内容**：命令行模式统一前置控制台保障；`--cli` 缺少 `--input` 时返回参数错误码；控制台不可用时输出落盘并提示。

**原因**：原实现依赖"一定有控制台"的假设，窗口化打包后该假设不成立；缺参场景走 `print` 后返回 2，同样受无控制台影响。

**影响**：同一套命令在源码与打包两种形态下行为一致，脚本可依赖退出码判断。
